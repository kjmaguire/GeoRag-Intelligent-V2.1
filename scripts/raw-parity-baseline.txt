# ONE MORE TRAP, for whoever ports the rest. The `Migrations under production
# privileges` CI job applies database/raw/phase0/*.sql as `bootstrap`, then
# migrates as `georag_ci` — deliberately not a member of bootstrap, never a
# superuser. Only three phase0 files CREATE SCHEMA, and measured against that
# job, two of them land: bootstrap ends up owning schema `interpretation` (4
# tables) and schema `backups` (1 table). A migration that CREATEs a table in
# a foreign-owned schema does NOT quietly skip on IF NOT EXISTS — Postgres
# resolves the creation namespace first and raises `permission denied for
# schema`. 2026_08_28_100400 hit exactly this and now stands down with a
# RAISE WARNING instead (note its ownership probes go through pg_class by
# NAME, since to_regclass() itself needs USAGE on the schema).
# backups.snapshot_runs is the remaining entry that will hit the same wall.
