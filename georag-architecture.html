00 — How to read this document

This is the single source of truth for GeoRAG's architecture. When code and this document disagree, the document is correct and the code needs fixing (or this document needs an explicit, deliberate update with a reason).

Status vocabulary (since v1.52): sections describe the target architecture; where the code has not caught up, an As built note dated 2026-09-06 says exactly what exists, and a Corrected note records what the section used to claim. Companion references: docs/architecture/manual/ (the file-cited "repair manual" — chapters 13–18 are missing from its own reading order), docs/adr/, docs/RUNBOOK.md, docs/acceptance-criteria.md. tests/Unit/ArchitectureDocSchemaParityTest.php asserts this file's schema tables against the migrations.

04b — Coordinate System Detection
StepProcessDetail
1Declared CRS winsSpatial files (georag_geoparsers/spatial_parser.py): the file-declared CRS (shapefile .prj, GeoPackage gpkg_spatial_ref_sys, GeoTIFF tags) always beats the upload's source_epsg override; the source CRS is captured before any transform. Tabular files (ingest_tabular.py): precedence is upload source_epsg → silver.projects.crs_epsg → DEFAULT_SOURCE_EPSG = 32613, and only the last case is flagged georef_method='assumed'.
2No guessingThere is no coordinate-range heuristic. A spatial file that declares no CRS, has no override, and is not a CRS-less format (.dxf / .dgn / .geojson / .json, which are 4326 by definition) is refused with crs_missing — assuming 4326 once mis-placed a shapefile. EPSG codes are bounded to 1024–32767 in the client, the controller and the chk_spatial_features_crs_native CHECK.
3Area-of-use confidence_score_crs_confidence scores the geometry against the CRS area_of_use: 1.0 inside, 0.5 partial overlap, lower outside. The score lands in crs_confidence on the feature; a project-bbox rejection is not performed.
4Transform + auditSpatial features are stored in EPSG:4326 (silver.spatial_features.geom) with crs_epsg_native retained. Collars are stored in the project CRS (silver.collars.geom, SRID 32613) plus a geom_4326 twin. The ZIP-path ingesters carry their own fixed transforms (e.g. cameco_log_ingester: EPSG:32155 → 32613).
Accuracy is reported per release against a validation corpus; no quality figures are claimed without a measured baseline. Per-workspace configurable project CRS.

04d — Format Inventory

Supported ingestion formats. V1 status is authoritative in §11b; this list inventories every format the architecture covers. New formats require main-session approval.

Upload categories are the contract (UploadController::CATEGORIES mirrored by resources/js/lib/uploadCategories.ts): reports (pdf, tif, tiff, rrd, jpg, jpeg) · archive (zip) · collars / surveys / lithology / samples (csv, txt, tsv) · excel (xlsx, xls, xlsm) · tables (dbf, dat, mdb, accdb) · spatial (geojson, json, shp, gpkg, gml, gpx, dxf, dgn, fgb, gdb, zip, qgs, qgz, tab, mif, str) · well_logs (las). A bare .zip resolves to archive. Retired categories that 422: seismic, xyz, geophysics. Roadmap: DOCX (§11b), SEG-Y, Geosoft GDB (binary channels — distinct from Esri .gdb), Geosoft grids, acQuire / Maxwell / Leapfrog / IOgas exports (IOgas blocked on a fixture), KML/KMZ. Maximum upload size is 512 MB by default (GEORAG_MAX_UPLOAD_BYTES); the PDF preflight separately caps at 2 GiB.

Format-name disambiguation: "Esri File Geodatabase" and "Geosoft GDB" share the .gdb extension but are unrelated formats. Esri's is a vector GIS container (read via GDAL/pyogrio's OpenFileGDB driver — in V1). Geosoft's is a binary geophysics channel store (proprietary SDK — Roadmap per §11b). Disambiguate at ingest by inspecting directory structure: Esri .gdb is a directory with gdb/a files; Geosoft .gdb is a single binary file.

04d-tile — Tile-Serving Layer (Martin)

Martin serves geological vector layers as Mapbox Vector Tiles directly from PostGIS SQL function and table sources. Martin is infrastructure — it owns no state. Its config (docker/martin/martin.yaml, auto_publish: false so *_history audit tables are never published) is baked into the image by docker/martin.Dockerfile because Azure Container Apps has no bind mount; compose and martin-cc run the same digest and serve identical tiles.

Connection & role

Martin connects directly to PostgreSQL on port 5432, not through PgBouncer (persistent connections + server-side features incompatible with transaction pooling). Own pool, pool_size: 20. The read-only role is martin_readonly (migration 2026_04_22_150000_grant_martin_readonly_select): SELECT on silver.collars, silver.drill_traces, silver.seismic_surveys, public_geo.jurisdictions and the eight public_geo.v_pg_*_mvt views, plus ALTER DEFAULT PRIVILEGES on both schemas. 04e — Core Data Schemas (PostgreSQL + PostGIS)

Geological domain schemas. Pydantic models mirror these for runtime validation. JSONB used for variable-key payloads. PostgreSQL roles: georag (owner; migrations only, via the pgsql_migrations connection direct on 5432), georag_app (runtime; created by database/raw/phase1/10-georag-app-role.sql, not by the image init), georag_read / georag_write / georag_audit (scoped roles from docker/postgresql/init/init-roles.sql), martin_readonly (§04d-tile), hatchet. Defense-in-depth — no GRANT georag TO georag_app. Tenant isolation is Postgres RLS: tenant_isolation policies on workspace_id, bound per request by BindWorkspaceRlsContext (Laravel) and app/db/scoped_pool.py (FastAPI); the 2026-08-24 sweep is catalog-driven and forces RLS on every RLS-enabled table it owns.

Eight core tables have no versioned CREATE. silver.projects, collars, surveys, lithology_logs, samples, reports, spatial_features and well_log_curves are only ALTERed, indexed and RLS-wrapped by migrations; their DDL was provisioned by hand and lives nowhere in the repository. A fresh cluster depends on the test-db provisioning migration to stand them up.

Porting is never transcription. Every batch of that work turned up a case where copying the raw DDL verbatim would have shipped something wrong, because later migrations had already reconciled the table and are guarded on it existing — so they ran, skipped, and will never fire again. Recurring traps: a table created after the one-shot 2026_08_24_010000 sweep needs an explicit FORCE ROW LEVEL SECURITY, since ENABLE alone lets the owner bypass its own policy; a column a guarded migration made nullable must be created nullable; and a CHECK must admit the values its writer actually emits.

Split ownership. Only three phase0 files CREATE SCHEMA for themselves (interpretation, backups, gold). On a cluster where an operator ran db:apply-raw first, those schemas are owned by whichever role ran it, and a migrating role that is not a member of it cannot create in them — CREATE TABLE IF NOT EXISTS does not quietly skip, it raises permission denied for schema, because Postgres resolves the creation namespace before the IF NOT EXISTS test. Migrations touching those three schemas stand down with a warning rather than failing the deploy. The Migrations under production privileges CI job reproduces exactly this split.

Permanently raw-only. gold.h3_density_mineral and silver.density_choropleth_h3 are the two remaining baseline entries and must not be ported: the table's h3_index column has type h3index, supplied by the h3 extension, which is absent from Azure Flexible Server's azure.extensions allow-list. A migration creating either would fail with type "h3index" does not exist and stop the chain. The H3 heatmap is capability-gated in routers/visualizations.py for this reason.

10r — Citation Precision Mode
As built (2026-09-06): answer_runs.citation_mode is CHECK-constrained to posthoc_span_resolution | hybrid_delayed_attachment, only the first is ever written, and there is no config knob to choose. inline_streaming_experimental does not exist. Partial-failure data lands in answer_runs.partial_failure_details / partial_resolution_rate, but no banner renders it and the split latency columns were never created (latency is Prometheus-side: FIRST_TOKEN_LATENCY).

Two-stage model: evidence-constrained generation (§04h, §09) followed by post-hoc claim-span resolution. Body streams first as delta events; citations follow as citation events after generation and attach to the final text in the UI.

ModeBehavior
posthoc_span_resolution (default)Body streams to completion, then spans resolved against bound evidence in a dedicated post-pass. Highest precision.
hybrid_delayed_attachmentBody streams; citations resolved in a sliding window with bounded delay. Lower latency, slightly lower precision.
inline_streaming_experimental (design only)Per-token citation hints during streaming. Not in the enum; known to misattribute on long-range claims.

Configurable at workspace level + environment default. Persisted per answer run in answer_runs.citation_mode.

Latency accounting

Target: generation_latency_ms + citation_latency_ms recorded independently in answer_runs. Not built; a single latency_ms was added and then dropped 2026-08-22.

Degraded behavior — partial citation failure

If body generation succeeds but citation resolution partially fails: answer body remains visible · unresolved spans marked as uncited · banner shows "Some citations could not be attached" · unresolved span count + resolver failure metadata logged to answer_runs · feedback path remains available so users can flag the uncited spans.
